# ssda-doc-review:文档审查规范

目标读者:文档审查员/子 Agent。读完能对本项目任何报告做规范化双轨审查并产出合格审查报告。

## 1. 什么时候必须用本 skill

- 审查课程报告(系统设计报告/测试报告/模型评估报告等)的格式与内容
- 文档合并、版本更新、提交前的质检
- 跨文档一致性核对(多个报告同时更新后)

## 2. 审查顺序与原则

**先格式、后内容、再一致性;只报告不修复**(修复由总控派回原负责方,避免审查者自改自审)。

## 3. 格式审查清单(docx)

用 postcheck.py 自动检查(python "<docx技能目录>/scripts/postcheck.py" <文件>):

- [ ] 9 项全过:blank-pages / cover-overflow / line-spacing / image-overflow / font-fallback / heading-levels / shading-type / toc / image-aspect-ratio
- [ ] 封面:标题语义断行、元信息表无折行、无多余空白页
- [ ] 目录:TableOfContents 存在、附"更新域"提示、三段式页码(封面无/目录罗马/正文阿拉伯)
- [ ] 图表:编号连续(图 2-1、图 3-1…)且正文有引用、图题在图下方居中、表格表头 tableHeader、行不跨页 cantSplit
- [ ] 中文正文:1.3 倍行距(line:312)、首行缩进 2 字符、两端对齐

Markdown 源文件:

- [ ] 标题层级连续(# 一、…二级 1.1/1.2)
- [ ] 编号体系正确:FR-01~13、M01~M10、P01~P05、TC-01~16(勿自创或写错)
- [ ] 表格语法正确(表头行 + 分隔行)

## 4. 内容审查清单

- [ ] **数字溯源**:报告中每个统计数字(用例数/接口数/缺陷数/百分比)能在仓库找到出处(文件:行号或报告章节);无出处数字标记 P1
- [ ] **跨文档一致性**(以仓库为准):公开接口 15 个、管理接口 19 组、数据库 12 张表、后端 134 / 前端 54 用例、GUI 走查 19 项(14 过/5 部分)、缺陷复核 8/8、契约 v1.1、检索修复 16.29 vs 6.57
- [ ] **编号正确性**:引用的需求/模块/用例编号与《需求分析说明书2.0》与契约一致
- [ ] **日期与版本**:日期格式 YYYY-MM-DD;文档版本记录存在
- [ ] **中文排版**:中英文之间加空格(如"134 用例")、全角标点、无错别字(抽查标题与首尾段)、无生硬直译
- [ ] **事实红线**:不出现与需求书冲突的表述(如把选做项写成已完成)、不泄露密钥/口令明文(admin/admin123 仅允许出现在安全提示上下文)

## 5. 审查报告模板(docs/report/文档审查报告.md)

```markdown
# 文档审查报告(第 N 轮)
- 审查范围:…/审查时间:…/审查人:文档审查员 Agent
## 一、结论(通过/有条件通过/不通过)
## 二、格式审查结果(逐文件 postcheck 摘要)
## 三、内容审查发现
| 编号 | 级别 | 文档:位置 | 问题 | 证据 | 建议 |
## 四、跨文档一致性核对表
## 五、修复建议汇总(交总控派发)
```

严重级别:P0=事实错误/数字造假;P1=数字无溯源/一致性冲突;P2=格式不合格/编号错误;P3=排版细节/文字瑕疵。

## 6. Do / Don't

**Do**:证据具体到文件与页码/段落;抽查优先覆盖"会被老师看"的位置(封面/目录/摘要/结论/图表);每轮审查附复核结论。

**Don't**:禁止直接修改被审文档;禁止凭印象写结论(每条必须有证据);禁止把"建议改进"写成"缺陷"(级别要如实)。

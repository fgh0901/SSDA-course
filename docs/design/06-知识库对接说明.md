# 知识库对接说明(交给知识库创建方)

> 项目:新生校园知识库与入学事务辅助系统 · 文档版本 v1.0(2026-10-25)
> 一句话职责边界:**知识库方负责"存数据 + 提供检索";本系统负责"提问理解 + 检索结果收敛 + DeepSeek 生成回答 + 来源展示"**。知识库方不需要实现问答,只需要"给一段问题,返回最相关的知识条目"。

## 一、我们期望的对接方式(方式 A:HTTP 检索接口,推荐)

知识库方提供一个 HTTP 查询接口,建议按以下约定实现(字段名可协商,格式一致即可):

**请求**

```http
POST {知识库地址}/retrieve
Content-Type: application/json

{ "question": "校园卡丢了怎么补办?", "topK": 5 }
```

**响应**

```json
{
  "items": [
    {
      "title": "校园卡遗失补办流程",
      "snippet": "一、挂失:登录校园卡自助服务平台或到一卡通服务中心办理挂失;二、补办:携带本人身份证到一卡通服务中心(综合服务楼 1 层 108 室)…",
      "source": "后勤服务处公告(2026-09)",
      "updatedAt": "2026-09-18 10:23:45"
    }
  ]
}
```

四个字段含义(检索器组装"带来源回答"的最低要求):

| 字段 | 含义 | 必填 |
|---|---|---|
| title | 条目标题(回答中展示并引用) | 是 |
| snippet | 与问题相关的正文片段(≤120 字为宜) | 是 |
| source | 原始出处(如"后勤服务处公告") | 是——可解释性要求 |
| updatedAt | 条目更新时间 | 建议 |

## 二、备选方式(若不方便提供 HTTP 接口)

| 方式 | 知识库方提供 | 我方工作 |
|---|---|---|
| B. 数据库直连 | 库类型/地址/**只读账号**/字段含义说明 | 我方新写一个检索器直连查询 |
| C. 数据导出 | 定期导出的 SQL/CSV/Excel | 我方导入本地库,零代码对接 |

## 三、对接后系统的行为(给知识库方的预期)

1. 学生提问 → 我方调用你们的检索接口(topK 默认 5,超时 5 秒);
2. 检索到内容 → 我方用 DeepSeek 基于[你返回的条目]生成回答,并附来源展示;
3. **你们接口超时/宕机 → 我方自动降级为本地检索模式,系统不报错、不中断**(所以接口稳定性要求宽松,重启期间不影响我们演示);
4. 你们**不需要**实现问答/生成——回答由我方大模型负责,只用你们的检索结果做范围收敛(保证答案不超出知识库范围)。

## 四、需要知识库方交付的清单

- [ ] 检索接口地址(或数据库连接信息,或导出文件)
- [ ] 接口鉴权方式(如 Token,无则说明"无鉴权")
- [ ] 四个字段的实际命名与含义对照(如与上方约定不同,给一份字段映射)
- [ ] 数据规模与更新频率说明(写入项目文档)

## 五、我方对接步骤(拿到上述信息后)

1. 实现/配置检索适配器:**`HttpKbRetriever` 已实装**(`backend/src/ai/retriever/http-kb-retriever.ts`,含 5s 超时与报文校验)——若对方按第一节约定实现,通常只需改字段映射;若报文不同,仅微调该文件;
2. `backend/.env` 配置 `KB_API_BASE_URL`(+ `KB_API_TOKEN` 如有),重启后端;
3. 验证:问一个**只在知识库中存在**的问题 → 回答应附知识库来源(retriever=http_kb);**停掉知识库 → 自动级联回本地检索器**(retriever=local_kb),服务不中断、页面无报错;恢复后自动切回;
4. 补充集成测试与文档(契约/部署文档同步)。

> 级联策略(2026-10-25 实装):外部库优先、失败回落本地,是鲁棒性设计的一部分;`examples/mock-knowledge-base/` 为联调与演示用的模拟外部库。

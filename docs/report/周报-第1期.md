# 项目周报(第 1 期)

- **项目**:新生校园知识库与入学事务辅助系统(《软件系统设计与应用》课程设计)
- **周期**:2026-10-09 ~ 2026-10-20(选题与需求阶段)
- **编写**:项目组(A 角色汇总)

## 一、本周完成工作

1. **选题确认**:确定「新生校园知识库与入学事务辅助系统」,面向新生与管理人员,系统内集成 AI 问答组件(知识库检索收敛回答范围)。
2. **需求调研与获取**:按利益相关者识别(新生/辅导员/后勤/系统管理员/评审教师)开展文档研究与虚拟访谈,形成调研问题清单与调研记录模板。
3. **用户故事与优先级**:整理 US-01~US-11 用户故事及验收要点(必须/应该/可以/扩展四级)。
4. **需求规格说明书三轮修订**:
   - V1.0(10-09,董珵):初稿,拟定标题分工、确定受众与产品预期;
   - V1.1(10-10,孙豫天):补齐需求规格、验证测试与实施计划;
   - V2.0(10-11,孙豫天):按评审意见与课件模板总体修订,补齐用户角色、量化非功能需求、填写约束与假设。
5. **业务建模**:10 个业务功能模块(M01~M10)、5 条主业务流程(P01~P05)、活动图与用例图、10 条核心验收测试用例(TC-01~10)。
6. **工程准备**:10-16 初始化 Git 仓库并配置 CI 骨架(课程材料检查);10-20 提交需求分析定稿与项目概览。

## 二、产出物

- 《需求分析说明书 2.0.docx》(需求规格说明书,含用户故事/模块/流程/活动图/用例图/接口示例/约束假设/验收用例)
- 仓库 `.github/workflows/ci.yml`(CI 骨架)、README

## 三、问题与风险

| 问题/风险 | 应对 |
|---|---|
| 技术栈存在双选(需求书写 SpringBoot 或 Node/Express) | 设计阶段裁决:Node.js+Express(与前端同语言、AI 流式友好、CI 已备) |
| AI 对话的"知识库"不由本项目组开发 | 确定边界:后端只留检索接口;开发期用自建数据 Mock |
| 团队首次采用多 Agent 协同开发 | 制定统一简报、契约先行、小步上库、worklog 监控机制(第 2 期落地) |

## 四、下期计划

2. 双端并行开发(M01~M10 + AI 降级链路);
3. 测试(单元/接口/GUI 黑盒)与阶段体检。

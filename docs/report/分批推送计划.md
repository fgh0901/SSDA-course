## 二、每周操作步骤(项目负责人执行)

```bash
# 1. 推送当周批次(截止提交号见总表;严格按顺序,禁止 force push)
git push origin <该批截止提交号>:main

# 2. 推送后到 GitHub 仓库 → Actions 页,确认三个作业(课程材料/前端/后端)全绿
# 3. 在周报文档补一段当周进展并提交(见下"每周配套")
```

## 三、每周配套(保持节奏自然)

1. **周报**:从第 3 周起,每周推送前在 `docs/report/周报-第N期.md` 追加当周进展(哪怕只有"本周完成 XX 检查/文档"),与推送互相印证。
2. **AI 使用日志**:当周如有 AI 辅助工作,在 `docs/ai-logs/开发过程AI使用日志.md` 追加记录(课程考核项)。
3. **CI 记录**:每次推送触发的 Actions 运行就是过程证据,无需额外截图(答辩时可展示 Actions 历史列表)。

## 四、注意事项

- 六批提交号必须**按表顺序**推送(后一批的提交号包含前一批,顺序推送为快进);若某周跳过,下次推最新截止号即可(跳过的批次自动包含)。
- 不要使用 `git push --force`;不要用 `git push` 直接推全部(会一次推到最新,破坏分批节奏)。
- 新工作(第 7 批起)正常小步提交,周末 `git push origin main`。
- 演示环境注意:`backend/.env`(含数据库口令)与 `docs/ai-logs/exports/` 均在 .gitignore 中,不会被推送。

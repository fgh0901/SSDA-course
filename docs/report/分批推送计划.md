## 二、每周操作步骤(项目负责人执行)

```bash
# 1. 推送当周批次(目标=上游;截止提交号见总表;严格按顺序,禁止 force push)
git push upstream <该批截止提交号>:main

# 2. 推送后到上游仓库 → Actions 页,确认三个作业(课程材料/前端/后端)全绿
#    https://github.com/paloma-dove/SSDA/actions
# 3. 从第 3 周起推送前补当周周报与 AI 使用日志增量(见下"每周配套")
```

## 三、每周配套(保持节奏自然)

1. **周报**:从第 3 周起,每周推送前在 `docs/report/周报-第N期.md` 追加当周进展(哪怕只有"本周完成 XX 检查/文档"),与推送互相印证。
2. **AI 使用日志**:当周如有 AI 辅助工作,在 `docs/ai-logs/开发过程AI使用日志.md` 追加记录(课程考核项)。
3. **CI 记录**:每次推送触发的上游 Actions 运行就是过程证据,无需额外截图(答辩时可展示 Actions 历史列表)。

## 四、注意事项

- 六批提交号必须**按表顺序**推送(后一批的提交号包含前一批,顺序推送为快进);若某周跳过,下次推最新截止号即可(跳过的批次自动包含)。
- 不要使用 `git push --force`;不要用 `git push` / `git push upstream main` 直接推全部(会跳过周次节奏)。
- **网络排障(2026-10-25 实测)**:直连 GitHub 可能报 `Connection was reset` 或 443 超时(国内网络常见);重试通常可成功,推荐命令:`git -c http.version=HTTP/1.1 push upstream <截止提交号>:main`(实测第 2 次重试即成功);有代理的话 `git config --global http.proxy http://127.0.0.1:<端口>` 后再推。
- **`.zcode/` 已移出版本库(10dfc67)**:该目录是 AI 工具本地配置,仅本地使用;第 1 批历史中带过的 12 个 .zcode 文件由该移除提交修正,**最终上游仓库不含 .zcode**。开发规范正文在 `docs/design/`,AI 过程证据在 `docs/ai-logs/`,均正常入库。
- 新工作(第 7 批起)正常小步提交,周末 `git push upstream main`。
- 演示环境注意:`backend/.env`(含数据库口令)与 `docs/ai-logs/exports/` 均在 .gitignore 中,不会被推送。

## 五、时区热修复与后续推送模式(2026-11-11 新增)

**事件**:第 2+3 批推送后(9d1233f),CI 后端作业 2 例失败——过期/临期天数断言差 1 天。根因:CI 的 mysql:8.0 容器时区为 UTC,而过期判定(CURDATE)与测试数据(东八区)的"今天"在跨零点时段相差一天(已在本机将 MySQL 切 UTC 精确复现,修复后转绿)。

**修复**:数据库连接池每个连接 `SET time_zone='+08:00'`——过期判定按北京时间,不随部署服务器时区漂移(对中文校园系统语义更正确)。本地 139/139 全绿(UTC 服务器与系统时区下各验证一轮)。

**热修复落位**:修复提交已摘送到第 3 批末尾形成 `hotfix/tz` 分支(本地),推送命令:`git push upstream hotfix/tz:main`(推送后 CI 复跑应转绿)。因推送当晚 GitHub 网络中断暂未推上,**网络恢复后先推这条**。

**后续批次推送模式(上游已含热修复提交,与本地历史分叉,需经合并推送)**:

```bash
git fetch upstream
git checkout -B push/4 c880f0c          # 在批次截止号上建推送分支
git merge upstream/main -m "merge: 同步时区热修复"
git push upstream push/4:main           # 快进推送(含第 4 批内容+热修复)
git checkout main
```

第 5/6 批同理(截止号换 74eda66 / fc36051);第 7 批(最终)直接 `git merge upstream/main` 入 main 后 `git push upstream main`。

# SSDA 部署文档

- 项目:新生校园知识库与入学事务辅助系统(SSDA)
- 日期:2026-10-25(对应仓库当前实现;后端 Express + TypeScript + MySQL,前端 Vue 3 + Vite)
- 适用场景:课程演示环境与本机开发环境部署

## 1. 环境要求

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | 22 及以上 | CI 使用 Node 22;本机开发实测版本 node v24.19.0 |
| npm | 随 Node.js 安装 | 前后端依赖安装与脚本执行 |
| MySQL | 8.0 | 本机开发实测版本 8.0.44;数据库仅使用 `ssda`(测试库为 `ssda_test`) |

操作系统不限:开发在 Windows 下完成,CI 在 ubuntu-latest 下运行,行为一致。

## 2. 数据库初始化

在仓库根目录按顺序执行(schema 先于 seed):

```bash
mysql -u root -p < db/schema.sql
mysql -u root -p < db/seed.sql
```

说明:

- `db/schema.sql` 自动建库 `ssda`(utf8mb4,排序规则 utf8mb4_0900_ai_ci),共 12 张表,含主外键、唯一约束与 CHECK 约束;脚本幂等(先 `SET FOREIGN_KEY_CHECKS=0` 再 DROP+CREATE),可重复执行。
- `db/seed.sql` 灌入管理员账号与演示数据:管理员 `admin / admin123`(口令以 bcrypt cost 10 哈希存储,明文凭据仅在该文件注释中注明一次)、6 个分类、46 条知识(覆盖已发布/已过期/待审/草稿/下架五种状态)、14 个地点、11 位教师、9 门课程及 12 条任教关系、10 条办事指南、8 条活动、6 条变更日志示例。
- **覆盖警告**:重新执行 seed 会清空并重建全部表数据。仅用于课程演示库,切勿对含有真实数据的库执行。

## 3. 应用配置(backend/.env)

后端配置经 zod 启动校验(`backend/src/config/env.ts`),必填项缺失或不合法时服务拒绝启动,错误信息指明具体字段。从模板复制后修改:

```bash
cd backend
cp .env.example .env
```

全部变量说明如下:

| 变量 | 默认值 | 必填 | 说明 |
| --- | --- | --- | --- |
| PORT | 3000 | 否 | 后端监听端口 |
| NODE_ENV | development | 否 | development / test / production;为 test 时不启用 morgan 请求日志 |
| DB_HOST | 127.0.0.1 | 否 | MySQL 地址 |
| DB_PORT | 3306 | 否 | MySQL 端口 |
| DB_USER | root | 否 | 数据库用户 |
| DB_PASSWORD | (空) | 是 | 改为本机 root 密码 |
| DB_NAME | ssda | 否 | 数据库名 |
| JWT_SECRET | (无默认) | 是 | 至少 16 字符;缺失或过短服务拒绝启动。示例值仅作本地占位,演示/部署必须更换 |
| JWT_EXPIRES_IN | 12h | 否 | 管理端登录态有效期 |
| CORS_ORIGIN | http://localhost:5173 | 否 | CORS 白名单,逗号分隔多个 origin |
| DEEPSEEK_API_KEY | (空) | 否 | DeepSeek API Key;不配置时 AI 对话自动降级(见第 5 节) |
| DEEPSEEK_BASE_URL | https://api.deepseek.com | 否 | DeepSeek 接口地址(OpenAI 兼容协议) |
| DEEPSEEK_MODEL | deepseek-chat | 否 | 使用的模型名 |
| LLM_TIMEOUT_MS | 20000 | 否 | LLM 请求超时(毫秒),超时自动降级 |
| KB_API_BASE_URL | (空) | 否 | 外部知识库地址(当前版本为预留项,见第 5 节) |
| KB_API_TOKEN | (空) | 否 | 外部知识库令牌(预留) |

**禁止提交 .env**:仓库根 `.gitignore` 已排除 `.env` 与 `.env.*`(仅豁免 `.env.example`)。提交前用 `git status` 自查,确认 `.env` 未被纳入。

## 4. 启动与验证

```bash
# 1. 启动后端(端口 3000)
cd backend
npm install
npm run dev        # tsx watch 热重载;启动成功输出 [ssda-backend] listening on http://localhost:3000 (development)

# 2. 启动前端(端口 5173,已配置 /api 代理到 3000)
cd ../frontend
npm install
npm run dev
```

生产构建方式:后端 `npm run build`(tsc 输出 dist/)后 `npm run start`;前端 `npm run build`。

启动后按以下三步验证:

1. **健康检查**:浏览器或命令行访问 `GET http://localhost:3000/api/health`,应返回 `{"success":true,"data":{"status":"ok","db":"up","time":"…"}}`;若 `db` 为 `down`,说明数据库未启动或 DB_* 配置有误。
2. **学生端**:访问 `http://localhost:5173/`,首页与知识库等页面能看到 seed 演示数据,说明"前端 → 代理 → 后端 → MySQL"全链路正常。
3. **管理端**:访问 `http://localhost:5173/admin/login`,使用 `admin / admin123`(seed 预置)登录,登录成功并可进入管理端工作台。

## 5. AI 组件配置

AI 对话组件(检索 + 生成)无需任何配置即可运行,按 `.env` 中 `DEEPSEEK_API_KEY` 是否配置自动切换:

- **未配置 Key(默认,降级模式)**:对话由本地检索器(LocalKbRetriever,仅检索已发布知识条目)命中结果模板化组织回答,回答首行固定注明「当前为降级模式……」;检索不到可信内容时固定拒答「知识库未覆盖该问题,请咨询相关部门核实。」,不调用大模型,也不返回 500。降级是预期行为,不是故障。
- **配置 Key(模型生成模式)**:在 `backend/.env` 填入 `DEEPSEEK_API_KEY` 后重启后端,即切换为 DeepSeek 模型生成(OpenAI 兼容协议,`DEEPSEEK_BASE_URL`/`DEEPSEEK_MODEL` 可改);调用超时(`LLM_TIMEOUT_MS`,默认 20 秒)或异常时自动回落降级模板,接口不报错。
- **外部知识库**:`.env` 中 `KB_API_BASE_URL` 为检索器工厂的预留项。当前版本外部知识库适配(HttpKbRetriever)尚未实装,配置该变量后仍使用本地检索器,不影响系统运行;后续实装后仅需修改配置即可切换,无需改动业务代码。
- **切换验证**:对话接口 `POST /api/ai/chat` 响应中的 `mode` 字段即当前模式(`deepseek`=模型生成,`fallback`=降级);管理端 AI 日志列表与 `npm run export:ai-logs` 导出统计均可核对。

## 6. CI/CD(.github/workflows/ci.yml)

工作流位于 `.github/workflows/ci.yml`,在推送到 `main`、针对 `main` 创建 Pull Request 或手动触发(workflow_dispatch)时运行;同分支/同 PR 的新运行会自动取消仍在进行的旧运行。共三个 job:

1. **course-materials**:校验课程材料存在(《软件系统设计与应用S》课程设计实施 - p.pdf、需求分析说明书2.0.docx)。
2. **frontend**(Vue 3 + Vite):Node 22 环境,依次执行 `npm ci` → lint → Vitest 测试 → 构建(vue-tsc + vite),并上传 dist 构件(保留 7 天)。
3. **backend**(Express + Jest + MySQL 8):Node 22 环境 + `mysql:8.0` 服务容器(root/root,预建 `ssda_test`,带 mysqladmin ping 健康检查与 30 秒启动等待);先等待数据库就绪并幂等确认 `ssda_test` 为 utf8mb4,再依次 `npm ci` → lint → 测试(Jest + Supertest,globalSetup 每轮重建 ssda_test 表结构)→ 构建(tsc)。CI 环境变量中 `JWT_SECRET` 为专用 ≥16 位测试值,与后端 zod 启动校验规则一致。

## 7. 常见问题(Windows)

1. **Git Bash 下 npm / mysql 命令不存在**:受 Windows 用户 PATH 引号问题影响,Git Bash 可能继承不到工具路径。临时修复:`export PATH="/c/Program Files/nodejs:$PATH"`(MySQL 客户端同理把其 bin 目录加入),或改用 PowerShell / CMD 执行。
2. **curl 发送中文出现乱码(检索"假空")**:Git Bash 的 `curl -d` 将中文按 GBK 编码发送,服务端按 UTF-8 解析得到乱码,曾导致接口冒烟误判"检索为空"。接口实测请改用 Node 发起请求(天然 UTF-8):
   ```bash
   node -e "fetch('http://localhost:3000/api/ai/chat',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({sessionId:'smoke',message:'军训时间'})}).then(r=>r.json()).then(console.log)"
   ```
   自动化测试一律使用 Supertest(Node 层 UTF-8),不受此影响。
3. **npm install 提示 esbuild 构建脚本被忽略(allow scripts)**:npm 出于安全默认不运行依赖的安装脚本并给出提示,不影响本项目——esbuild 的平台二进制以可选依赖形式随包发布,前端开发与构建均正常;如需消除提示,可按 npm 提示允许该脚本后重新安装,不处理亦可。
4. **端口占用**:3000(后端)或 5173(前端)被占用时,Windows 下用 `netstat -ano | findstr :3000` 找到 PID,`taskkill /PID <pid> /F` 结束占用进程;或将 `backend/.env` 的 `PORT` 改为其他端口(前端 `frontend/vite.config.ts` 的代理 target 需同步修改);5173 被占时 Vite 会自动顺延端口,以前端控制台实际输出地址为准。

## 8. 安全清单(演示/部署前逐项确认)

1. **更换 JWT_SECRET**:`backend/.env` 中不得使用 `.env.example` 的示例值,须改为 ≥16 位随机串;缺失或过短服务会拒绝启动(zod fail-fast)。
2. **修改管理员默认口令**:`admin / admin123` 仅用于课程演示,演示或部署前请通过管理端修改管理员密码(口令以 bcrypt 哈希存储)。
3. **.env 不入 git**:`.gitignore` 已排除 `.env` / `.env.*`;每次提交前以 `git status` 复核,严禁将含密钥与数据库口令的 `.env` 提交入库。
4. **既有安全基线(随代码生效,无需额外配置)**:SQL 全参数化、口令 bcrypt 哈希、CORS 白名单、管理接口 JWT 鉴权、错误响应不泄露堆栈与内部凭据。

## 1 项目概况

- **项目名称**:新生校园知识库与入学事务辅助系统的设计与实现。
- **课程背景**:《软件系统设计与应用》课程设计,要求软件工程与 AI 结合——系统内集成至少一个 AI 组件、体现 AI 特殊需求(可解释/鲁棒/公平/隐私),每阶段提交 AI 使用日志。
- **项目目标**:集中管理新生常用的校园教学、地点、办事、活动信息;支持分类浏览、关键词检索与含来源/更新时间/有效期/核实状态的详情展示;提供管理员后台维护(含审核发布与过期信息处理);集成 AI 问答组件(知识库检索收敛回答范围,回答附来源、不可信即拒答)。
- **技术路线**(已冻结):前端 Vue 3 + TypeScript + Vite + Element Plus;后端 Node.js + Express + TypeScript + mysql2(参数化 SQL);数据库 MySQL 8.0;校验 zod;鉴权 JWT + bcryptjs;AI 生成 DeepSeek API(deepseek-chat,OpenAI 兼容),AI 检索 KnowledgeRetriever 接口(默认 LocalKbRetriever,预留 HttpKbRetriever)。
- **本期不做**:收藏(US-10)、学生账号、在线报名、支付、教务系统对接、统一身份认证、地图导航。
- **交付形态**:学生端 SPA(11 页)+ 管理端 SPA(9 页)+ 后端 API(公开 15 个、管理 19 组)+ 数据库脚本(12 张表)+ 全套课程文档(需求分析说明书 2.0、API 契约 v1.1、系统设计文档四件套、测试/审计/验收报告、AI 使用日志双轨记录)。

## 4 风险与应对(实际发生的风险记录)

执行过程中实际发生并已解决的三项环境/平台风险(来源:worklog-orchestrator 2026-10-24 16:05/19:10、worklog-backend 问题记录、dev-usage-log 故障记录):

| # | 风险 | 现象 | 根因 | 应对与结果 |
|---|---|---|---|---|
| 1 | Windows PATH 引号问题 | npm 可运行,但 npx/npm 派生子进程报"'node' 不是内部或外部命令" | 用户级 Windows PATH 中 nodejs 目录带引号("C:\Program Files\nodejs"),cmd 子进程无法解析 | 每条涉及 npm 的命令前置 `export PATH="/c/Program Files/nodejs:$PATH"`(会话级,不改注册表);已写入全部 Agent 派单注意事项;另确立管道后用 PIPESTATUS 校验真实退出码 |
| 2 | curl 中文 GBK 乱码 | 冒烟测试中文关键词经 curl(Git Bash)发送后服务端检索"假空",一度误判为缺陷 | Git Bash 的 curl -d 按 GBK 编码发送中文,服务端收到乱码 | 改用 Node fetch(UTF-8)复核确认链路正常——环境假象非缺陷;测试一律用 Supertest(Node 层 UTF-8)规避,记入开发规范 |
| 3 | 服务端风控拦截 | 以自定义角色类型派发后台 Agent 连续 3 次在 1 秒内失败,报"request has been blocked due to unusual activity" | 自定义角色类型的后台派发链路触发平台风控(非服务端整体封锁) | 改用 general-purpose 类型派发并将角色职责完整写入任务书;角色定义文件保留 .zcode/agents/(手动开启对话不受影响);后续阶段沿用此模式 |
